## How the "backend" works

The Python pipeline (`predicting_course_failure_early.py`) remains the compute backend. Exporter scripts (in `../scripts/`) ran it unchanged — same seeds, grids, splits and threshold logic — for both `USE_G1` settings and dumped every result into `index.html`:

- Test metrics + confusion matrices for Decision Tree & Random Forest (default 0.50 vs recall-tuned)
- Chosen thresholds (RF 0.41 / DT 0.53 mid-term; RF 0.32 / DT 0.05 pre-term)
- OOF threshold sweeps (power the interactive threshold explorer)
- Top-12 feature importances, watchlists, per-student test risks, risk histogram
- A depth-4 surrogate tree distilled from the Random Forest (R² 0.93) so the risk simulator runs live in the browser
- The 649-student 3D scatter cloud powering the hero

Headline result (mid-term, Random Forest, threshold 0.41): **recall 0.92, 2 of 25 real failures missed, watchlist = 52 students (32% of class)**.

## Frontend features

- **3D**: hero canvas scatter of all 649 real students (G1 × absences × past failures, colored by outcome) with drag-rotate, inertia, depth fog and hover tooltips; 3D tilt cards; animated risk gauge.
- **Motion**: scroll reveals, count-up KPIs, aurora background, ticker, `prefers-reduced-motion` respected.
- **Dynamic updates**: one timing toggle (mid-term ↔ pre-term) drives the whole page; interactive threshold explorer; live search/filter/sort watchlist; browser-side risk simulator; light/dark theme; scroll-spy nav.
- **Carousels & scroll-snap**: auto-advancing model-card carousel (dots, arrows, hover-pause) and scroll-snap galleries for pipeline steps and team members.
- **Style**: "Aurora Glass" design system — dark-first education-analytics look with indigo→cyan gradients, glass cards, consistent tokens, responsive from 375 px up.

Ethics: the watchlist supports teacher judgement only — never for labelling, ranking or penalising students.
